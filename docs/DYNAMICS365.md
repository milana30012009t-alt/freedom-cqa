# Встраивание в Microsoft Dynamics 365

Интерфейс — обычные HTML/CSS/JS-файлы без сборки и внешних библиотек, все пути относительные, данные идут через REST API сервера. Поэтому его можно встроить в Dynamics 365 двумя способами.

## Способ 1 (рекомендуется): iframe на форме обращения

1. Разверните сервер CQA в сети компании под HTTPS (например, `https://cqa.company.kz`; Node.js ≥ 18, `npm start`, обратный прокси nginx / Azure App Service).
2. В `.env` сервера:
   ```
   HOST=0.0.0.0
   FRAME_ANCESTORS='self' https://<ваша-организация>.crm4.dynamics.com
   ```
   (`FRAME_ANCESTORS` попадает в заголовок `Content-Security-Policy: frame-ancestors` — без него браузер не покажет страницу внутри Dynamics.)
3. В конструкторе формы (например, «Обращение») добавьте элемент **iframe** с адресом:
   ```
   https://cqa.company.kz/?embed=1&conversation=<ID диалога>
   ```
   или включите передачу параметров записи — Dynamics передаёт их в параметре `data`, приложение понимает оба варианта (`?embed=1&data=<ID>`). ID без префикса ищется в активном наборе данных; можно указать полностью: `DEV:p1-ru-022`.
4. `embed=1` скрывает боковое меню — остаётся карточка диалога с оценкой, доказательствами и апелляциями.

## Способ 2: интерфейс как веб-ресурсы Dynamics

1. Загрузите файлы `public/` и `shared/` как веб-ресурсы с сохранением структуры папок (например, `new_/cqa/index.html`, `new_/cqa/js/...`, `new_/cqa/css/...`, `new_/cqa/shared/...`). Пути в интерфейсе относительные, поэтому префикс веб-ресурсов не мешает.
2. В веб-ресурсе `js/config.js` укажите адрес сервера:
   ```js
   window.CQA_CONFIG = { apiBase: 'https://cqa.company.kz' };
   ```
3. На сервере разрешите источник Dynamics: `CORS_ORIGINS=https://<ваша-организация>.crm4.dynamics.com`.
4. Добавьте веб-ресурс `index.html` на форму или в область приложения.

## Что важно для промышленного варианта

- **Авторизация.** Сейчас роль переключается в шапке (демо). В Dynamics роль и имя должны приходить из учётной записи: сервер уже принимает их в заголовках `x-cqa-role` / `x-cqa-user` (`server/http/http-utils.js → actorFrom`), их нужно заполнять на стороне шлюза после проверки токена Microsoft Entra ID, а не из браузера.
- **Секреты** (ссылка API организаторов, подписанные ссылки на записи, ключ AI) остаются на сервере CQA и не попадают в Dynamics.
- **Данные** можно получать не из API хакатона, а из сущностей Dynamics (обращения, переписка, звонки): нужен адаптер, который приводит записи к формату `conversation_id / channel / language / transcript[] / audio_url` — остальная система не меняется.
- **Хранение** — заменить JSON-файлы на БД (Dataverse / SQL) в `server/storage`.
- **Стиль.** Цвета и отступы — CSS-переменные в `public/css/tokens.css`; их можно привести к теме Dynamics без изменения разметки.
