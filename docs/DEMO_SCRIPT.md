# Демонстрация для жюри — 5 минут

Сценарий следует официальному регламенту: продукт → автоматическая оценка → апелляция → изменение чек-листа. Цифры ниже — для офлайн-правил (правила `rules-2026.11.2`, чек-лист с дословными формулировками PDF) на DEV-наборе. Без ключа модели это **автоматическая предварительная оценка, а не AI** — так и говорите жюри; с подключённым AI баллы могут отличаться, механика та же.

## Подготовка (за 15–30 минут до выступления)

```zsh
cd ~/Downloads/freedom-cqa
npm run reset -- --checklists        # официальный чек-лист v1, без оценок и апелляций
npm start                            # DEV загрузится из API (или: npm run import -- dev.json --activate)
# во втором окне терминала:
npm run evaluate -- --engine ai      # все 65 диалогов заранее (≈ $2.6–3.3); без ключа: --engine rules
```

- Если оценивали AI: откройте `p1-ru-006` и нажмите **«Офлайн-правила»** — для минуты 5 нужна мгновенная переоценка без ожидания модели.
- Роль в шапке — **Оператор**, в поле «Ваше имя» — имя выступающего.
- Вкладки браузера: Обзор · `#/c/DEV%3Ap1-ru-022` · `#/c/DEV%3Ap1-en-007` · Чек-лист · `#/c/DEV%3Ap1-ru-006`.
- Проверьте звонок `p4-ru-003`: запись должна играть (подписанные ссылки могут истечь — тогда плеер честно сообщит об этом, транскрипт и оценка остаются).
- Масштаб браузера 90–100 %, ноутбук на зарядке, уведомления выключены.

## Минута 1 — продукт (0:00–1:00)

**Обзор.** «Отдел качества вручную слушает и читает малую долю обращений. CQA оценивает каждый диалог по официальному чек-листу, показывает, *где именно* ошибка, и отдаёт спорное человеку».

- Показать: средний балл, распределение, частые проблемы, **грубые нарушения** (обход компании, раскрытие данных, оскорбление) и **сигналы риска** (запрос SMS-кода), очередь ручной проверки.
- **Диалоги**: 65 записей, RU/KZ/EN, чаты и звонки; фильтр «Только с нарушениями/рисками»; поиск. Открыть **p1-ru-022**.

## Минуты 2–3 — автоматическая оценка (1:00–3:00) — главный момент

В карточке **p1-ru-022**:

1. **Итог 31,25** и метка «Грубая ошибка». Баннер: «Предложение платной услуги в обход компании · 01:23» — нарушение выделено отдельно и **не обнуляет** итог (так в официальном чек-листе), диалог получает критический приоритет проверки.
2. **Критерии** по разделам: ответ, баллы, вес после перераспределения. Раскрыть **04 «Корректная и полная консультация» — 0 из 20**: обоснование + реплики-доказательства.
3. **Переход к доказательству:** нажать на цитату «Скиньте деньги мне на карту…» — транскрипт прокручивается к реплике 01:23 и подсвечивает её.
4. **Пример N/A:** **03 «Идентификация» — N/A**, «Почему N/A: общий вопрос, данные счёта не раскрывались»; вес перераспределён — открыть «Как рассчитан балл» (формула: вес × доля / сумма применимых весов × 100, округление до 2 знаков).
5. **Грубое нарушение:** вкладка «Нарушения и риски» — подтип, реплика, время; проверяющий может подтвердить или отметить ложное срабатывание.
6. (если есть время, 15 с) Звонок **p4-ru-003**: плеер, отметки доказательств на шкале, клик по времени реплики → перемотка; сигнал «Запрос SMS-кода — возможно, штатная процедура».

Фраза: «Баллы ставит не модель и не правила, а код. Автоматическая оценка — сейчас офлайн-правила, с ключом — AI-модель — отвечает по шкале каждого критерия и обязана сослаться на реплики; итог считается по весам из конфигурации. Без модели это предварительная оценка, её подтверждает проверяющий».

## Минута 4 — апелляция (3:00–4:00)

1. Открыть **p1-en-007** (английский диалог, пояснения на русском). Раскрыть **05 «Эмпатия» — Нет**: автоматическая оценка сочла финальное «Thanks for contacting us. Bye.» пренебрежительным.
2. **«Оспорить оценку»** → комментарий: «Оператор был вежлив, клиент недовольства не выражал; пропущенный вопрос уже учтён в 04 и 06» → «Отправить апелляцию» (статус «Новая»).
3. В шапке переключить роль на **Проверяющий** → **Апелляции** → открыть апелляцию → **«Взять в работу»** (статус «Ожидает рассмотрения»).
4. **«Изменить оценку» → «Да»** — превью: **54,62 → 77,69**. Причина → **«Сохранить решение»** (статус «Изменена»), история действий.
5. «Открыть диалог»: итог **77,69**, «Исходно: 54,62», у критерия — «решение проверяющего». Исходная оценка не удалена.

## Минута 5 — изменение чек-листа (4:00–5:00)

1. **Чек-лист → «Изменить → новая версия»**. В блоке «Расчёт итога» поле **«Порог первой реакции, с»: 180 → 60**. «Что изменено»: «Порог первой реакции 1 минута».
2. **«Сохранить как новую версию»** (сделать активной) → в окне выбрать **«Позже»**. Показать: появилась **v2**, v1 сохранена; «Изменения от v1».
3. Открыть **p1-ru-006** (первая реакция оператора — 132 с): баннер «Оценка выполнена по v1, активна v2» → **«Переоценить по v2»**.
4. Панель **«Что изменилось после переоценки»**: **100 → 95,5**, «06 Управление диалогом: 10 → 7», обоснование: «первая реакция через 132 с (порог 60 с) без извинения за ожидание».
5. Финал: «Изменение через интерфейс, без кода, сразу влияет на оценку. На контрольном наборе через 23 часа достаточно ввести новый group_id — новые диалоги оценятся по активной версии». (Опционально: «Диалоги» → «Переоценить устаревшие» — 33 из 65 диалогов меняют оценку.)

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| API организаторов недоступен | Данные уже загружены (хранятся локально); при необходимости — «Данные и AI» → файл |
| AI не отвечает / нет ключа | Оценка автоматически выполняется офлайн-правилами и помечается — демонстрация не прерывается |
| Ссылка на запись истекла | Плеер показывает причину; транскрипт и оценка доступны |
| Нужно начать заново | `npm run reset` (оценки и апелляции) или `npm run reset -- --checklists` (ещё и версии чек-листа), затем `npm run evaluate` |
