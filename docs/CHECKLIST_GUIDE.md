# Как добавить или изменить критерий

Чек-лист — версионируемая конфигурация. Любое изменение сохраняется как **новая версия**; существующие версии не меняются, каждая оценка хранит снимок версии, по которой выполнена. Исходный код менять не нужно.

## Через интерфейс (основной способ)

1. **Чек-лист** → выберите версию (активная отмечена) → **«Изменить → новая версия»**.
2. Отредактируйте:
   - **Расчёт итога**: правило N/A, округление, политика грубых ошибок, порог первой реакции (используется критерием 06, AI-промптом и аналитикой).
   - **Секции**: добавить, переименовать, удалить пустую.
   - **Критерии**: раскройте строку критерия → номер, ID, секция, название, описание (формулировка, которую видит AI и проверяющий), пояснение для единообразной оценки, тип ответа и шкала/варианты, роль (с весом / флаг без баллов), вес, разрешён ли N/A и при каком условии, режим оценки, офлайн-детектор и его параметры. Порядок — стрелками, исключить — снять «включён» или удалить из новой версии.
   - **«Добавить критерий»** — новый критерий в конце списка.
3. **«Проверить»** — проверка схемы (ошибки блокируют сохранение, предупреждения — нет).
4. Заполните «Что изменено» и нажмите **«Сохранить как новую версию»** (флажок «сделать активной» включён по умолчанию).
5. Система предложит переоценку: **«Переоценить все»**, **«Переоценить устаревшие»** (оценённые по другой версии) или **«Позже»**. Переоценить один диалог можно из его карточки: баннер «Оценка выполнена по чек-листу vN, активна vM → Переоценить по vM».
6. В карточке диалога после переоценки появляется панель **«Что изменилось после переоценки»**: итог до/после, версии, движок и построчные изменения по критериям. Вкладка «История» — все оценки с кнопкой «Сравнить с предыдущей».

Другие действия на странице: «Сравнить с vN», «Изменения от vN», «Сделать активной» (откат на любую версию), «Экспорт JSON», «Импорт JSON».

### Что происходит с прежними решениями проверяющего

При переоценке решение по критерию переносится в новую оценку, только если не изменились транскрипт, формулировка, варианты ответа и условия N/A этого критерия, а также общие параметры чек-листа, которые этот критерий использует (порог первой реакции — для 06). Иначе решение остаётся в истории прежней оценки, в новой отмечено «решения не перенесены — нужна повторная проверка», а диалог получает приоритет ручной проверки. Решения по остальным критериям переносятся.

## Через JSON (импорт)

Экспортируйте текущую версию («Экспорт JSON»), измените файл и загрузите через «Импорт JSON» (или `POST /api/checklists/import`). Файл проверяется так же, как в редакторе.

### Пример: новый критерий с офлайн-детектором

```json
{
  "id": "offer_more_help",
  "code": "09",
  "section_id": "conduct",
  "name": "Предложение дополнительной помощи",
  "description": "Да — перед завершением оператор спросил, остались ли у клиента вопросы.",
  "guidance": "Засчитывается любая формулировка на языке клиента.",
  "answer_type": "binary",
  "binary": { "yes_label": "Да", "no_label": "Нет" },
  "weight": 5,
  "scoring_role": "weighted",
  "na_allowed": true,
  "na_condition": "Клиент покинул чат до завершения.",
  "enabled": true,
  "evaluation_mode": "auto",
  "detector": {
    "type": "keyword_presence",
    "params": {
      "phrases": "остались вопросы\nещё вопросы\nтағы сұрақ\nanything else",
      "position": "last"
    }
  }
}
```

Веса не обязаны давать в сумме 100: итог всегда приводится к `max_score` (100) с учётом N/A.

### Поля критерия

| Поле | Значения | Назначение |
|---|---|---|
| `id` | латиница, цифры, `_`/`-`, до 40 символов | Ключ в оценках и апелляциях. При замене смысла критерия задайте новый ID |
| `code` | строка | Номер для отображения («01») |
| `section_id` | ID секции | Группировка и итог по разделам |
| `name`, `description`, `guidance` | текст | Название, официальная формулировка, пояснение команды. AI получает все три |
| `answer_type` | `binary` / `scale` / `options` | Да/Нет; числовая шкала (`scale.min`, `scale.max`, `scale.steps[{value,label}]` или `scale.step`); варианты (`options[{value,label,score}]`, `score` — доля веса от 0 до 1) |
| `weight` | число ≥ 0 | Номинальный вес |
| `scoring_role` | `weighted` / `flag` | С весом — в итоге; флаг — отметка без баллов (как «08 Грубые ошибки»), можно задать `flag_subtypes` |
| `na_allowed`, `na_condition` | bool, текст | Разрешён ли N/A и когда |
| `enabled` | bool | Выключенный критерий не оценивается |
| `evaluation_mode` | `auto` / `llm` / `rules` | AI, если подключён (иначе детектор); только AI (без AI — «не оценён»); всегда детектор |
| `detector` | `{type, params}` | Офлайн-детектор, см. ниже |

### Офлайн-детекторы

| Тип | Что проверяет | Параметры |
|---|---|---|
| `contact_greeting` | Приветствие на языке клиента и представление | — |
| `need_discovery` | Выявление потребности, уточняющие вопросы, повторные переспрашивания | — |
| `identification` | Идентификация до раскрытия данных счёта | — |
| `consultation_completeness` | Полнота ответа по существу (шкала) | — |
| `empathy` | Вежливость и реакция на недовольство | — |
| `dialog_management` | Переспрашивания, ответы не по порядку, ожидание без предупреждения, первая реакция | `silent_wait_sec` (порог первой реакции — общий параметр чек-листа) |
| `closing` | Итог/предложение помощи + прощание; обрыв клиентом → N/A | — |
| `gross_errors` | Оскорбление, услуга в обход компании, раскрытие конфиденциальной информации | — |
| `keyword_presence` | Обязательная фраза оператора | `phrases` (по строке; `/regex/` поддерживается), `position` (`any` / `first` / `last`) |
| `keyword_absence` | Запрещённая фраза оператора | `phrases` |
| `response_time` | Скорость реакции | `first_response_sec`, `reply_gap_sec` |

Если у критерия нет подходящего детектора и AI не подключён, критерий получает статус «не оценён» (итог помечается как предварительный, диалог уходит на проверку) — балл не придумывается.

### Общие настройки версии

```json
"scoring": {
  "max_score": 100,
  "na_policy": "redistribute_proportional",
  "rounding": { "mode": "half_up", "decimals": 2 },
  "critical_policy": "flag_only"
},
"parameters": { "first_response_threshold_sec": 180 }
```

- `na_policy`: `redistribute_proportional` (официальное), `redistribute_within_section`, `count_as_full`.
- `rounding.mode`: `half_up` (официальное), `half_even`, `floor`, `ceil`, `none`.
- `critical_policy`: `flag_only` (официальное — отметка без изменения балла), `zero_total`, `cap_total` (+ `critical_cap`).
- `risk_rules`: дополнительные сигналы вне чек-листа (`otp_request` — запрос SMS-кода/пароля, `profit_promise` — обещание доходности); не меняют балл, отправляют диалог на проверку.

## Как AI использует чек-лист

В промпт передаётся активная версия: инструкции и примечания чек-листа, общие параметры, сигналы риска и все включённые критерии, кроме режима `rules`, — с формулировками, пояснениями, допустимыми ответами (ступени шкалы, варианты) и условиями N/A. Модель возвращает только ответ по шкале каждого критерия с доказательствами; ответ проверяется по схеме, итог считает код. Поэтому изменение формулировки, шкалы или условия N/A сразу влияет на AI-оценку после переоценки.
