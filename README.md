# Freedom CQA — Conversation Quality Analytics

Веб-прототип для отдела контроля качества Freedom Broker: оценивает работу операторов в чатах и звонках (RU / KZ / EN) по настраиваемому чек-листу, показывает **доказательства** (реплика + время), отдельно выделяет **грубые нарушения**, поддерживает **апелляции и ручной пересмотр**, хранит **версии чек-листа** и сразу применяет изменения к оценке.

Итоговый балл всегда считает детерминированный модуль по весам и правилам из конфигурации; AI (или офлайн-движок правил) только предлагает ответы по критериям с обоснованием и ссылками на реплики.

- Без зависимостей: только Node.js 18.15+ (рекомендуется 22 LTS, проверено на 22). `npm install` не нужен.
- Данные — API организаторов по `group_id` (с повторами и проверкой ответа) или JSON-файл.
- AI — Claude (Anthropic API), любая OpenAI-совместимая модель (в т. ч. локальная через Ollama) или офлайн-движок правил без ключей.
- Интерфейс — HTML/CSS/JS без сборки, строгая CSP, режим встраивания для Microsoft Dynamics 365.

## Быстрый старт на MacBook (Apple Silicon M1–M4, zsh)

```zsh
# 1. Node.js (если ещё нет): нужна версия 18.15 или новее
brew install node
node -v

# 2. Папка проекта (после распаковки архива)
cd ~/Downloads/freedom-cqa

# 3. Настройки: адрес API организаторов и (по желанию) ключ AI
cp .env.example .env
open -e .env        # вставьте DATASET_API_URL, при наличии — ANTHROPIC_API_KEY

# 4. Запуск
npm start
open http://127.0.0.1:3000
```

При первом запуске сервер сам загрузит набор `DEV` из API (если задан `DATASET_API_URL`). Без API загрузите файл — см. ниже. Остановить сервер: `Ctrl+C`. Сменить порт: `PORT=3001 npm start`.

### Загрузка данных

**Вариант А — API организаторов.** В `.env` укажите `DATASET_API_URL` — ссылку кнопки «Открыть GET для DEV» из PDF-задания. Параметр `group_id` приложение подставляет само (по умолчанию `DEV`, переменная `DATASET_GROUP_ID`). Ссылка подписана — она хранится только в `.env` на сервере, не попадает в браузер, логи и Git (в логах виден только хост с пометкой «параметры скрыты»).

Загрузить или обновить набор можно в интерфейсе: **Данные и AI → API организаторов → group_id → «Загрузить из API»**. Повторы при сетевых ошибках, проверка структуры, отбрасывание дубликатов `conversation_id` — автоматически.

Проверить API из терминала (одинарные кавычки обязательны в zsh из-за `?` и `&`; пробел в начале строки не даст команде попасть в историю, если включено `setopt HIST_IGNORE_SPACE`):

```zsh
 curl -sS -G 'ВСТАВЬТЕ_ССЫЛКУ_ИЗ_PDF' --data-urlencode 'group_id=DEV' -o dev.json
head -c 300 dev.json
```

**Вариант Б — файл.** Сохранённый ответ API (в т. ч. `.txt`, внутри которого JSON):

```zsh
npm run import -- ~/Downloads/dev.json --group DEV --activate
```

или в интерфейсе: **Данные и AI → Локальный JSON-файл → «Выбрать файл»**.

**Контрольный набор (23-й час).** В интерфейсе: **Данные и AI** → введите выданный `group_id` → «Загрузить из API» (набор станет активным) → **Диалоги** → «Оценить неоценённые». То же через API сервера (подписанная ссылка не нужна, она уже в `.env`):

```zsh
curl -sS -X POST http://127.0.0.1:3000/api/datasets/fetch \
  -H 'content-type: application/json' -d '{"group_id":"ВЫДАННЫЙ_ID","activate":true}'
```

Новые диалоги оцениваются по **активной** версии чек-листа (включая изменения, сделанные в интерфейсе).

### Подключение AI

| Режим | Что указать в `.env` | Примечание |
|---|---|---|
| Офлайн-правила (по умолчанию) | ничего | Многоязычные эвристики RU/KZ/EN, мгновенно, бесплатно. Базовый уровень: не оценивает грамотность и бессвязность, сомнительные случаи отправляет на ручную проверку |
| Claude | `ANTHROPIC_API_KEY=...` (модель по умолчанию `claude-sonnet-5-5`) | Структурированный JSON по схеме, кэширование промпта, 1 вызов на диалог (+1 повтор при невалидном ответе) |
| OpenAI | `OPENAI_API_KEY=...`, `OPENAI_MODEL=...` | `OPENAI_RESPONSE_FORMAT=json_schema` |
| Локальная модель (Ollama) | `OPENAI_BASE_URL=http://localhost:11434/v1`, `OPENAI_MODEL=qwen2.5:14b`, `OPENAI_RESPONSE_FORMAT=json_object` | Без отправки данных наружу |

`AI_PROVIDER=auto` выбирает Claude → OpenAI-совместимую модель → офлайн-правила. Если AI недоступен, оценка выполняется правилами и помечается в интерфейсе (`AI_FALLBACK_TO_RULES=true`). Ключи хранятся только на сервере.

Оценить все диалоги заранее (перед демонстрацией):

```zsh
npm run estimate                      # прогноз стоимости по фактическому размеру промптов
npm run evaluate -- --engine ai       # или --engine rules; --all — переоценить уже оценённые
```

Стоимость и токены — в [docs/AI_AND_COST.md](docs/AI_AND_COST.md).

## Что где в интерфейсе

| Раздел | Что показывает |
|---|---|
| **Обзор** | Средний балл, распределение, частые проблемы, грубые нарушения и сигналы риска, очередь ручной проверки, путь клиента (бот → оператор, время первой реакции) |
| **Диалоги** | Поиск по ID и тексту, фильтры (язык, канал, статус, балл, нарушения, проваленный критерий, апелляции), сортировка, массовая оценка |
| **Карточка диалога** | Транскрипт со стилями ролей и временем, восстановленная кодировка (оригинал по клику), итог и критерии с обоснованием, переход к доказательству с подсветкой реплики, «Как рассчитан балл», нарушения и риски, история оценок и сравнение версий, аудиоплеер для звонков с синхронизацией |
| **Апелляции** | Очередь по статусам (Новая → Ожидает рассмотрения → Подтверждена / Изменена → Закрыта), спорная оценка, фрагмент диалога, решение с живым пересчётом итога, полная история |
| **Чек-лист** | Версии (неизменяемые), редактор → новая версия, активация, сравнение версий, импорт/экспорт JSON, проверка схемы |
| **Аналитика** | Баллы по языкам и каналам, доля провалов по критериям, повторяющиеся проблемы, темы, качество текста, использованные движки |
| **Данные и AI** | Загрузка из API / файла, переключение `group_id`, статус AI, прогноз стоимости |

Роль переключается в шапке: **Специалист КК** (подаёт апелляции) / **Проверяющий** (решает апелляции, меняет оценки, подтверждает нарушения). Это демо-переключатель без авторизации; имя для истории действий — поле «Ваше имя».

## Чек-лист

Начальная конфигурация — официальный «Чек-лист качества чатов» из PDF (8 критериев, веса 10/15/20/20/15/15/5, критерий 08 «Грубые ошибки» — флаг без баллов, N/A с пропорциональным перераспределением веса, округление до 2 знаков, порог первой реакции 3 мин): `checklists/freedom-official.v1.json`.

Изменить критерий: **Чек-лист → «Изменить → новая версия»** → поправить → «Сохранить как новую версию» (флажок «сделать активной») → предложение переоценить диалоги. Старые оценки сохраняют снимок своей версии; в карточке видно, что изменилось. Подробно — [docs/CHECKLIST_GUIDE.md](docs/CHECKLIST_GUIDE.md).

```zsh
npm test              # модульные + интеграционные (68 тестов)
npm run test:unit
npm run test:integration
```

10 тестов используют реальный DEV-набор; если файла `data/datasets/DEV.raw.json` нет (или переменной `CQA_DEV_FILE`), они пропускаются с пояснением. Загрузите набор (API или `npm run import`) — и они выполнятся.

## Безопасность и данные

- Подписанные ссылки (API, записи звонков) и ключи AI — только в `.env` и `data/` на сервере; оба в `.gitignore`. Браузер получает записи через прокси `/api/audio/:id`.
- Транскрипт передаётся модели как данные внутри `<transcript_data>`; системный промпт запрещает выполнять инструкции из диалога. Ответ модели проверяется по схеме; невалидные значения не превращаются в баллы.
- Пользовательский текст выводится только как текст (без `innerHTML`); строгая CSP без inline-скриптов.
- История апелляций, решений и версий чек-листа не удаляется (в интерфейсе и API нет операций удаления).
- Общая статистика не содержит цитат из диалогов.

## Известные ограничения

- Офлайн-движок правил — эвристический базовый уровень (ключевые фразы и структура диалога). Он не оценивает грамотность и бессвязность (это указано в обосновании критерия 06) и может ошибаться на нестандартных формулировках; для качества нужен AI.
- Анализ звонков — только по транскрипту. Интонация, тембр, эмоциональность и дикция не анализируются.
- Подписанные ссылки на записи могут истекать — тогда плеер сообщает об этом, оценка и транскрипт доступны.
- Роли — демо-переключатель без авторизации; для промышленного варианта нужна интеграция с SSO / Dynamics 365.
- Хранение — JSON-файлы (достаточно для сотен диалогов); для промышленного объёма — заменить на БД (слой хранения изолирован в `server/storage`).
